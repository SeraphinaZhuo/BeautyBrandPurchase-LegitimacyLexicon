# BPLL v2 验证协议

**版本：** v2.0.1  
**状态：** 首轮外部模型验证待运行

## 1. 验证阶段

### 阶段 A：自然分布筛查 Demo

- 36 条未见文本；
- 资生堂、SK-II、花王各 12 条；
- T1/T2 各 18 条；
- 24 条一般样本和 12 条危机富集样本；
- 与 120 条探索样本和 60 条关键案例无重叠；
- 研究者 reference 已在外部模型运行前冻结。

该阶段主要检验模型是否能够在低信息文本中保留 R5、O6 和 O7，而不是看到危机词就过度推断客户流失。

### 阶段 B：信息富集 challenge set

阶段 A 完成错误分析后，从未见语料中另行抽取 24–36 条信息较充分的案例，覆盖 O1–O5、T、MR、MX 与 D 的重要边界。该集合用于检验稀有标签，不与阶段 A 合并估计自然分布。

### 阶段 C：独立真人验证

Codebook 稳定后，邀请一名未参与 v1 和 v2 形成过程的标注者，独立完成至少 60 条、优选 100–120 条重叠样本。先报告人—人一致率，再进行分歧裁决。裁决后的结果才能称为 gold set。

## 2. Gemini 重复运行

对阶段 A 使用三个全新对话，分别运行 `gemini_demo_run_1`、`gemini_demo_run_2`、`gemini_demo_run_3`。三次输入文件与 Prompt 完全一致。聊天产品无法严格锁定温度，因此用独立重复评估稳定性。

## 3. 指标与暂定阈值

| 对象 | 指标 | 暂定阈值 |
|---|---|---|
| R | agreement、Gwet’s AC1 | agreement ≥ 0.90；AC1 ≥ 0.80 |
| O | agreement、Gwet’s AC1 | agreement ≥ 0.85；AC1 ≥ 0.80 |
| R1 下的退出/非退出 | precision、recall、F1 | precision 与 recall 均 ≥ 0.85 |
| T | micro-F1、Jaccard | micro-F1 ≥ 0.80；Jaccard ≥ 0.75 |
| MR/MX/D | micro-F1、逐标签 F1 | micro-F1 ≥ 0.80；出现 ≥5 次的标签 F1 ≥ 0.70 |
| 三次模型重复 | 同组指标 | 不明显低于模型—研究者一致性 |

阈值是工作流诊断标准，不是36条样本能够支持的最终性能声明。正例少于5条的标签只报告案例和计数。

## 4. 版本纪律

- 模型运行前冻结 Codebook、Prompt、Schema、映射和 reference；
- 原始模型输出只读保存，不静默修正；
- JSON 格式修复必须另存，并记录修复指令；
- 如果根据模型错误修改规则，版本升号，当前 Demo 转为开发集；
- 新版本的最终性能必须使用新的未见 holdout。

## 5. 公开报告

公开报告可以披露聚合指标、混淆类型和不可反向检索的改写案例。逐条原文、reference、模型原始输出和可定位 manifest 保持私有。
